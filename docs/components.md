# Components

Living inventory of the shared UI and logic surfaces. One row per reusable
component: what it is, every surface that uses it, and its parameters/variants.
Present-tense, current state only — history lives in git.

**Two standing rules:**

1. Any commit that touches a shared surface, or adds one, updates the matching
   row in the **same commit**. This file is always current, never archaeological.
2. Coverage claims in reports ("all media tabs", "every download surface") cite a
   row here — this table is the source, not prose.

**Convention — swallowed errors (25.07, third find of the class; sharpened
01.08):** a `catch` that drops an error, or a `try?` on a throwing call, is
only allowed when the same block carries a comment saying WHY dropping is
correct there. Sharpened by the gpodder incident: `try? decode(…) ?? empty`
on a RESPONSE BODY is the same class — an unreadable 2xx (captive portal,
proxy page) must THROW (`GPodderError.badPayload` pattern, pure parser +
first-120-bytes log), never decay to "no data" when empty is a meaningful
value (B30 sharpening candidate noted for the tooling agent). And:
**cancellation is never translated into a domain error** — `CancellationError`
/ `URLError.cancelled` propagate (or are handled as cancellation), they never
become "network failed" or similar (see `SubsonicClient.isCancellation`).

**Convention — change detection (25.07, third find of the class):** never
detect content changes via `count` — same count, different content (a swapped
subscription) misses the change. Use content identity (`ContentToken.of`,
hash of the IDs) or a store `generation`/`contentVersion` counter (pattern:
`PodcastRecommendationsStore.contentVersion`).

**Convention — observation goes into the smallest leaf (26.07, third round of
the class):** a container that carries scroll content NEVER observes
frequently-changing state. Observation belongs in the smallest leaf that
actually renders the value; frequently-changing = anything that can change
during a gesture (scroll offset, `collapsed`, download progress, player
position). Root cause of the hitch that survived all five bisect switches:
LibraryView (host of all five tab trees) observed `BottomBarState.collapsed`,
so every flip re-evaluated every mounted tab mid-scroll. The ONE observing
leaf is `BottomBarCollapseReader` (bar zone + toolbar icons); state mutations
are method calls on the shared instance (`runWhenCalm`/`reset`/`expand` — calls
don't observe). Prior rounds: TF4/E1 (`MediaAvailabilityScope`), cell-cost
sweep (row leaves).

**Convention — no title/state transitions inside a bar transition (27.07,
df69f6b damping, two stages):** changing `navigationTitle` state in the SAME
transaction as a tab flip on a live large-title bar permanently drops the
title (iOS 26 bug family, FB18304716 — no community workaround). LibraryView
therefore (b) decouples `barTitle` (own `@State`) from `selectedMediaType` —
retargeted one main-actor tick after the flip — and (a) verifies afterwards
via `NavigationBarNudge` (the ONE tightly-scoped UIKit introspection point)
that a VISIBLE title label actually exists in the bar; if not, it forces a
large-title rebuild by toggling `largeTitleDisplayMode` (public API only).
Empirics: the drop leaves the label invisibly in the tree (a naive existence
check reads "healthy"), (b) alone was flaky over long runs, a BLIND nudge on
every flip made things worse — detect-then-rebuild is the working shape.
This is a marked INTERIM damping; the root fix is per-tab NavigationStacks
(compat-sprint item 9), where constant titles remove the bug condition.

**Letzter-Tab (01.08):** `selectedMediaType` persists across launches
(`lastSelectedTab`; restored only when the tab's MASTER toggle is on). Seeded
journeys keep the deterministic Home start unless they pass `-uitest-keeptab`
— otherwise every journey would inherit the previous one's tab.

**Convention — tab selection vs availability (01.08, Y37 hardening):** the
tab SELECTION is user intent and only a user act moves it — the tab's master
toggle (pure `TabSelectionPolicy.shouldFallBackToHome`, tested). Transient
availability (server unreachable without VPN, ABS podcast probe pending,
`PodcastSubscriptions`' ASYNC initial load) never changes the selection; an
unavailable-but-selected tab shows its own offline/empty state. Root cause of
"podcast tab keeps getting deselected": every `sourcesVersion` bump inside the
start window (subs still decoding + probe unanswered) threw the selection to
Home via the old availability check. The Y37 bump handler logs the full
source state (`Y37 sources changed …`) — device-readable diagnosis stays in.

**Convention — cell heights in lazy containers (26.07, second round of the
class):** cells in `LazyVGrid`/`LazyVStack`/horizontal card rows have a height
INDEPENDENT of their data. Every text line uses `lineLimit(n, reservesSpace:
true)`; every optional slot (eyebrow, subtitle, meta, progress bar) is always
laid out and reserves its space — render an invisible placeholder (`" "` /
`.opacity(0)`) instead of dropping the line. Otherwise the ScrollView corrects
the offset when the real height diverges from the estimate (the weak scroll
bump, Apple Forums 685461). Applies to: `MediaRowContent` (all four slots) ·
`MediaTile` (title+subtitle) · `BookGridCell` · `AlbumCell` ·
`SeriesStackCell` · `RecentShowTile` · `MusicContinueCard` ·
`RadioStationCard`. List-backed rows (native UITableView sizing) are exempt
but converge via the shared components anyway.

**Convention — settings placement (Variante b, 25.07):** every setting belongs
to EXACTLY ONE category: **source · library · playback · storage · sync ·
system/diagnosis**. Media-type-specific settings go on that type's settings
pill (Audiobooks: playback · Podcasts: recommendations); cross-cutting ones go
on General, in the fixed order Sources → Libraries → Sync → Storage →
Notifications → Appearance → Statistics → About → Diagnostics. New settings
inherit this rule instead of being appended at the end (that is how the
diagnosis switches ended up squatting in About). A media pill exists only when
the type is enabled AND has at least one own setting.

**Convention — l10n gate (26.07, after two straight misses; extended same
day):** whoever adds user-visible strings runs the B15 l10n-coverage lint
against the WORKING TREE before the commit and adds the new hits to
`Localizable.xcstrings` WITH a German translation — or deliberately marks them
`verbatim` (debug/diagnosis class below). AND: whenever a commit touches the
string catalog itself, B1 `xcstrings-lint` (catalog health: missing/stale/
duplicate) runs before the commit too — `missing` is a STOP. B15 catches
"in code, not in catalog"; B1 catches "in catalog, but untranslated" (an
Xcode sync can pull in old never-translated literals). Translation-invariant
keys (format specifiers, proper nouns) carry `shouldTranslate: false` instead
of fake translations.

**Convention — Debug UI (agreed with the reviewer, 25.07):** debug/diagnosis UI (bisect
switches, diagnosis toggles, build stamps) uses `Text(verbatim:)` (for labels:
`Label { Text(verbatim: "…") } icon: { Image(systemName:) }`) and NEVER enters
the string catalog — no entries, no translations. This keeps the B15
l10n-coverage lint sharp for REAL missing localizations instead of blunting it
on throwaway switches. New debug controls inherit this.

Convention: cross-media behaviour and reused UI is **one parametrised component**
used by every relevant surface (Regel 2). A new media tab wires the existing
components rather than forking them.
